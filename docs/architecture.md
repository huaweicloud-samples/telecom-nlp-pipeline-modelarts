# 架构说明 — 自定义 NLP 流水线（实体识别 / 词向量 / 情感分类）

> 本文档以华为云视角描述本实践的架构，为独立最佳实践。

## 一、业务场景

基于电信行业推文语料，构建三条 NLP 能力：

1. **自定义实体识别**：从设备名列表训练 DEVICE 实体识别模型，从推文中抽取手机/设备名
2. **词向量训练**：在推文语料上训练 Word2Vec 词向量（100 维），供下游特征工程使用
3. **负面情感分类**：训练文本分类器，对推文实时判断 NEGATIVE / POSITIVE

## 二、总体架构

## 三、组件与职责

| 组件 | 用途 | 说明 |
|------|------|------|
| ModelArts Notebook | 训练与验证 | 三个 Notebook 分别承载实体识别 / 词向量 / 分类训练；支持 GPU/CPU |
| OBS | 数据与模型产物存储 | 训练数据、CoNLL 标注、模型产物统一存放，桶 ACL private |
| IAM 委托 | 权限面 | `modelarts` 服务委托代理 OBS，训练作业/Notebook 免密钥访问数据 |
| （可选）ModelArts 推理端点 | 在线推理 | 分类器/实体识别模型部署为在线端点，提供 REST 调用 |
| （可选）FunctionGraph + APIG | 轻量上线 | 将 fastText 分类器封装为函数，APIG 暴露分类接口 |

## 四、数据流

1. 数据准备：实体列表（Text,Type CSV）与推文语料来自仓库 `data/` 目录
2. 转换：CSV 标注 → CoNLL（`src/scripts/csv_to_conll.py`），供 BERT-NER 消费
3. 训练：三个 Notebook 在 ModelArts 中分别产出 NER 模型 / 词向量 / 分类器
4. 存储：产物上传 OBS（`src/scripts/upload_to_obs.py` 或 obsutil）
5. 推理：实体抽取与情感分类在 Notebook 内直接验证，或部署为在线端点

## 五、能力选型说明（详细对照见 others/）

| 能力 | 可选实现 | 本实践实现 | 差异说明 |
|------|--------|-----------|---------|
| 自定义实体识别 | 托管 NLP 服务一键训练 | 自建 BERT-NER 微调 | 需自行管理训练管线与数据格式转换 |
| 词向量 | 托管词向量训练容器 | gensim 训练作业 | 超参对齐，产物格式一致 |
| 文档分类 + 端点 | 托管分类器 + 托管端点 | fastText + 可选部署 | 轻量可复现，精度依赖标注质量 |
| 数据存储 | 对象存储 | OBS | 概念对等 |
| 权限 | IAM 角色 | IAM 委托 | 概念对等 |
